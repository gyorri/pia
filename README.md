# PIA v0.3.24 — 모바일 게시물 상세 X 레이아웃 동기화

## 기준과 변경 범위
사용자가 첨부한 실제 X 모바일 게시물 상세 캡처 `60093.jpg`와 PIA 화면 `60098.jpg`를 기준으로 비교했습니다. **공개 화면의 게시물 상세만 조정하고, 타임라인의 기존 6개 반응 아이콘·관리자 기능·DB API는 변경하지 않습니다.**

이 패치는 **v0.3.22의 공개 화면 `app.js`/`style.css`/`index.html`**을 기준으로 작성되었습니다. v0.3.23은 별도의 관리자 전용 수정이므로 그대로 유지할 수 있습니다. GitHub 운영 main을 실시간으로 읽어 현재 변경 사항과 비교한 것은 아닙니다.

## 이번 변경 내용
- 상세 화면 하단 반응 바를 실제 X 캡처의 **답글 · 리포스트 · 좋아요 · 북마크 · 공유** 5개로 구성합니다. 상세 하단의 조회수 그래프 아이콘은 제거합니다.
- 목록형 타임라인은 기존 **답글 · 리포스트 · 좋아요 · 조회수 · 북마크 · 공유** 6개 아이콘을 유지합니다.
- 실제 X 캡처의 상세 공유 아이콘을 참고해 **세 점 연결 공유 아이콘**을 상세 화면에만 적용합니다. 실제 링크 복사 기능은 유지합니다.
- 상세 날짜 표기 순서를 **`오후 9:11 · 2026년 10월 20일`** 형식으로 변경합니다.
- 게시물 데이터의 `view_count`가 숫자로 존재하는 경우 날짜 오른쪽에 **`· 1만 조회수`** 같은 축약 표기를 추가합니다. 값이 없으면 조회수를 표시하지 않으며, **가짜 숫자를 만들지 않습니다**.
- 상세 아이콘 5개의 가로 위치를 X 모바일 캡처에 가깝게 정렬합니다. 목록/답글 카드의 일반 반응 바 구조는 그대로 유지합니다.
- 브라우저 캐시로 변경이 보이지 않는 일을 줄이기 위해 `public/index.html`의 앱 리소스 버전을 `v43`으로 갱신합니다.

## 스크린샷 비교 및 테스트
- 실제 X 캡처는 너비 1536픽셀로, 너비 384 CSS 픽셀 비교 시 약 4배 배율 기준으로 환산했습니다. X 다섯 아이콘 중심의 근삿값은 `28, 110, 192, 274, 356px`입니다.
- Chromium 너비 384px 샘플 테스트에서 PIA 다섯 아이콘의 측정값은 `27, 108, 190, 271, 352px`였습니다.
- Chromium 화면 폭 320, 375, 384, 390, 425, 600, 1440px에서 상세 5개/타임라인 6개 아이콘, 가로 넘침 없음, JavaScript 오류 없음 확인.
- 날짜/조회수 유효값 및 값 누락 시 처리 확인. 예시 수치(1만 조회수)는 **브라우저 테스트 전용 샘플값**이며 실제 DB 데이터가 아닙니다.
- 실제 운영 데이터, Cloudflare Pages 배포, 모바일 사용자의 네이티브 브라우저에서의 픽셀 단위 동일성은 확인하지 않았습니다.

## 패치 포함 파일
- `public/app.js` — 상세 반응 바 HTML, 조회수/날짜 서식, 상세 전용 공유 아이콘
- `public/style.css` — 상세 전용 5개 아이콘 위치, 타이포그래피 및 반응형
- `public/index.html` — 정적 JS/CSS 캐시 버전 변경
- `README.md`, `HISTORY.md` — 변경 설명과 이전 이력 유지

## 적용 안내
1. 현재 운영 GitHub main에 추가 변경이 있으면 먼저 비교/병합하고 백업합니다.
2. ZIP을 풀어 GitHub 저장소 루트에 상대 경로 그대로 덮어쓰고 커밋합니다.
3. Cloudflare Pages 배포 완료 후 브라우저를 새로고침합니다.
4. 게시물 **상세 화면의 5개 아이콘**, **타임라인의 6개 아이콘**, 날짜/조회수, 공유 버튼, 모바일 가로 넘침을 확인합니다.

**DB 마이그레이션은 필요하지 않습니다.** 이번 공개 화면 수정은 v0.3.23 관리자 파일을 덮어쓰지 않습니다.

# PIA v0.3.23 — 관리자 반복 입력 개선

- `날짜수정필요` 체크박스와 날짜 필드를 하나의 레이아웃으로 배치하고 체크박스 너비를 17px로 고정해 정렬 깨짐 해소

3. 커밋 후 Cloudflare Pages 배포를 확인하고 관리자 페이지에서 새로고침합니다.
4. **DB 마이그레이션 불필요.** 기존 DB 데이터는 변경하지 않습니다.

# PIA v0.3.22 — 실제 X 캡처 기준 액션 바 정렬 보정

## 기준과 목적
사용자가 제공한 PIA/X 게시물 하단 캡처를 정렬 기준으로 사용했습니다. **v0.3.20 기반 전체 공개 화면 구성에 v0.3.21의 액션 그룹 마크업을 포함하고, v0.3.22에서 액션 중심 위치를 보정**한 통합 패치입니다. v0.3.21 선적용은 필요 없습니다.

이 패치는 *공개 화면 디자인 보정*입니다. 운영 사이트의 현재 GitHub 소스와 대조한 것은 아니므로 운영본의 추가 기능이 있다면 무조건 덮어쓰지 말고 먼저 비교하세요.

## 이번 변경
- 캡처의 본문 시작점을 기준으로 아이콘의 상대 위치를 재측정했습니다. 이전 PIA의 균등 간격 6개 대신, **답글·리포스트·좋아요·조회수는 앞쪽 그룹에 넓게 배치하고 북마크·공유는 오른쪽 가까이 묶는 방식**을 보정했습니다.
- 본문과 액션 바 사이의 세로 간격을 목록에서 약 4px 줄였습니다.
- 목록 액션 바의 왼쪽 시작 위치와 오른쪽 끝 위치를 보정하고, 각 아이콘 숫자는 해당 아이콘에 붙어 표시되도록 유지했습니다.
- 상세 게시물 액션 바는 목록용 음수 여백을 적용하지 않도록 분리했습니다.
- CSS/JS 리소스의 캐시 버전을 `?v=42`로 갱신했습니다.
- 기존 v0.3.20의 화면 개선과 v0.3.21 액션 마크업을 **하나의 ZIP**으로 포함하며, 기존 인용 카드 이동/수동 답글/날짜 붙여넣기/검색 새로고침 코드를 유지했습니다.

## 실제 캡처 측정 근거
첨부된 X 이미지에서 본문 시작점 기준으로 추정한 아이콘 중심의 가로 위치 비율: 대략 `1%, 24%, 46%, 69%, 91%, 97%`.

로컬 Chromium 모의 데이터, 가로 425px 화면에서 실제 보정본 아이콘 중심 비율: `1.14%, 23.65%, 46.15%, 68.66%, 90.31%, 97.15%`.

*이 값은 주어진 두 캡처 및 모의 브라우저 렌더링을 기준으로 한 비교이고, 운영 X 웹사이트 전체에 대해 픽셀 단위 일치를 보장하지 않습니다.*

## 변경 파일
- `public/app.js` — v0.3.21 액션 그룹 구조를 포함한 이전 기능 통합본
- `public/style.css` — v0.3.20 디자인 + v0.3.22 배치 보정
- `public/index.html` — 정적 CSS·JS 캐시 버전 갱신
- `README.md`, `HISTORY.md` — 설명/이전 이력 보존

## 적용 방법
1. 운영 GitHub `main`과 현재 배포 상태를 확인하고 백업합니다.
2. ZIP을 풀어 저장소 **루트에 같은 경로로 덮어쓰기**합니다. 기존 버전 이후 별도로 수정한 파일이 있다면 먼저 비교/병합합니다.
3. GitHub 커밋 후 Cloudflare Pages 배포를 확인합니다.
4. 브라우저 강력 새로고침 뒤 게시물 하단 아이콘 6개, 답글 개수, 공유 버튼, 인용 카드/검색/모바일을 확인합니다.
5. 문제가 있으면 배포 전 GitHub 커밋으로 되돌립니다.

## 검증 범위

- Chromium 모의 데이터: 320px/400px/425px/434px/600px/1440px 화면 가로 넘침 없음.
- 상세 게시물 렌더링, 검색, 인용된 기존 게시물 이동 성공.
- ZIP CRC 검증 통과.
- 관리자 DB·API 변경 없음, 신규 D1 마이그레이션 없음.
- **운영 사이트 실제 데이터·Cloudflare 배포 상태는 미검증**.

## 이전 버전 설명(원문 보존)

# PIA v0.3.20 — 공개 X 화면 전체 정밀 보정 패치

> **기준본**: 이전에 제공한 v0.3.18까지의 기능 통합 소스 + v0.3.19 화면 개선 의도. 이 대화에서 실제 운영 중인 GitHub `main`의 최신 상태와 DB는 확인하지 않았습니다. 기존 파일을 별도로 수정했다면 먼저 변경 내용을 비교하세요.

## 핵심 개선
- 사용자 제공 **실제 X 하단 액션바**와 **PIA 하단 액션바** 캡처를 바탕으로 답글·리포스트·하트·조회수·북마크·공유 6개 아이콘 SVG를 새로 보정했습니다.
- 6개 액션을 일관된 터치 영역과 간격으로 재배치했습니다. 댓글 수는 **실제로 연결된 답글 수**에서만 계산하고, 좋아요/리포스트/조회수는 **데이터 필드가 있을 경우에만** 표기합니다.
- 카드의 작성자·아이디·날짜 한 줄, 프로필 이미지와 본문 간격, 인용 카드의 외곽선과 줄바꿈, 반응 아이콘 hover 색상 등을 조정했습니다.
- 게시물 상세에 원글 중심의 헤더, 본문, 전체 날짜/시간, 액션 구분선, 연결된 답글 레이아웃을 조정했습니다.

- 기존 게시물 인용 연결, 기존 작성 날짜 붙여넣기, 검색 최신 DB 새로고침 등 **v0.3.18까지의 로직을 유지**하도록 통합했습니다. 특히 과거 v0.3.19가 v0.3.9 코드를 바탕으로 만들어졌던 잠재적 덮어쓰기 문제를 바로잡았습니다.
- 새로운 게시물/반응 데이터를 만들거나 서버 기능을 추가하지 않았으며, 관리자·CSV 가져오기·D1 테이블을 변경하지 않았습니다.

## v0.3.17 — CSV 중복 등록 이중 방지

### 변경
- CSV 미리보기에서 기존 DB와 CSV 내부의 **동일 계정·동일 본문·동일 작성 시각**을 중복으로 판정하여 **체크 불가** 처리합니다. 본문은 유니코드 NFKC 및 공백 묶음 정규화, 시각은 시간대 포함 절대 시각으로 비교합니다.
- 동일 계정·본문이지만 작성 시간이 다른 게시물은 **중복 후보**로 표시하고 기본 선택을 해제합니다. 실제로 별도 게시물이라면 사용자가 수동 체크하여 등록할 수 있습니다.
- `needs_review`만 있는 행은 계속 기본 선택합니다. 기존 날짜/답글/인용 데이터 및 매칭 방식은 유지합니다.
- 저장 버튼을 누른 직후 최신 DB 데이터를 다시 읽고 중복을 재검사합니다. 저장 중에도 CSV 전용 `import_guard` 플래그를 통해 서버에서 기존 DB와 재비교합니다.
- 서버는 같은 시각의 정규화된 글을 확인하고, 새 CSV 등록 건에 고유 지문을 부여해 `pia_import_keys`에 기록합니다. D1 트랜잭션과 기본키 충돌을 이용해 동시에 실행된 CSV 등록의 중복 삽입을 막습니다.
- **기존에 저장된 게시물은 변경/삭제하지 않으며**, 중복 게시물이 이미 있더라도 마이그레이션을 적용할 수 있습니다. 일반 수동 게시물의 작성·수정 API 동작은 기존대로입니다.

### 반드시 지킬 적용 순서
1. 현재 GitHub 소스가 **v0.3.16까지 반영**되어 있는지 확인하고 운영 D1 백업을 합니다. 이전에 인용 연결 기능을 사용했다면 `migration-v0.3.13.sql`이 적용됐는지도 확인하세요.
2. **`migration-v0.3.17.sql`을 운영 Cloudflare D1에 먼저 1회 적용**합니다. 예: `npx wrangler d1 execute <D1_DATABASE_NAME> --remote --file=migration-v0.3.17.sql` (실제 D1 DB 이름으로 대체).
3. ZIP의 파일을 저장소 루트에 경로 그대로 덮어쓰기 → 커밋 → Cloudflare Pages 배포.
4. CSV 일괄 등록 화면에서 DB와 중복 재검사, 중복 후보 수동 선택, 동일 파일 재업로드 차단을 확인하세요.

### 제한 및 주의
- 일괄 등록에서의 정확한 중복 차단 기준은 **같은 @아이디, 같은 정규화 본문, 같은 작성 시각(동일 절대 시각)**입니다. 서로 다른 시각의 유사 글을 무조건 삭제하지 않습니다.
- 서버가 처리하는 자동 중복 차단은 CSV 가져오기 요청에 한정됩니다. 일반 수동 게시물 저장과 외부에서 임의로 보내는 쓰기 요청 전체를 막는 전역 유일 제약은 아닙니다.
- 기존 DB에 있는 중복 기록을 자동 제거하지 않습니다.
- 실제 Cloudflare 운영 DB/브라우저 배포 검증은 수행하지 않았습니다. JS 문법, 마이그레이션 SQL, ZIP 무결성 및 모의 흐름 테스트만 수행했습니다.

## v0.3.18 — 삭제된 게시물의 검색 잔상 개선

### 수정 범위
- 공개 타임라인: 검색 화면으로 이동하거나 검색어를 다시 검색할 때 `/api/data`의 최신 결과를 요청합니다. 요청 중에는 이전 검색 결과를 잠시 숨겨 삭제된 글이 남아 보이지 않도록 합니다.
- 브라우저 탭 재활성화 및 관리자/공개 화면의 게시물 변경 알림 시 최신 게시물 목록으로 갱신합니다. 새로고침이 실패한 검색 화면에는 이전 게시물을 다시 표시하지 않고 오류를 알립니다.
- 관리자: 게시물 목록 검색, 답글 대상 검색, 인용 원본 검색에서 최신 DB를 다시 읽습니다. 다른 탭에서 게시물이 삭제된 뒤 관리 화면에 돌아오면 검색 목록과 중복 안내를 갱신합니다.
- API: 삭제 대상이 없거나 연결된 답글 때문에 삭제할 수 있는 상태가 아닌 경우 구체적인 오류를 반환합니다. 실제 삭제 행 수를 확인한 후에만 삭제 성공을 반환합니다. **연결된 답글을 자동 삭제하지 않습니다.**
- 스크립트 캐시 버전: `public/index.html`의 `app.js` v39, `public/admin.html`의 `admin.js` v38.

### 설치
