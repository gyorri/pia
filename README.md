# PIA v0.3.31 — OCR 답글 누락 방지 보정

## 패치 적용 기준
- **v0.3.30 캡처 OCR 패치가 적용된 PIA**를 기준으로 합니다. 운영 GitHub main의 실제 최신 소스는 확인하지 못했습니다.
- 변경: `public/capture.js`(답글 분리 및 상태 메시지), `public/capture.html`(JS 캐시 버전 31), `README.md`, `HISTORY.md`. 추가: `tests/capture-replies.test.cjs`.
- 기존 계정/게시물 등록, 클립보드 연속 붙여넣기, 고정밀 인식, 중복 검사, 공개 페이지, 관리자 관리 기능, 서버 API 및 DB 스키마는 변경하지 않습니다.
- 유료 API 사용 또는 결제 설정 **없음**. 브라우저 내 무료 Tesseract.js OCR 유지.

## 무엇이 바뀌었나
1. `관련성이 가장 높은 HE v`, `관련성이 가장 높은 답글 Vv`처럼 **답글 제목의 마지막 글자가 깨진 경우**, 이전 게시물의 날짜/반응수와 다음 작성자 헤더 및 `님에게 보내는 답글`을 **복합적으로 확인**하여 별도 답글 후보로 분리합니다.
2. 답글 제목 자체가 누락돼도, 이전 글의 날짜·반응수가 나오고 **다른 작성자 줄 뒤에 답글 수신자 표시가 있으면** 게시물 후보로 분리합니다. 작성자 헤더가 판독되지 않아도 답글 수신자 표시를 기반으로 본문이 사라지지 않도록 보완했습니다.
3. 단순히 `관련성이 가장 높은 답글`이란 말이 **일반 게시물 본문에 등장한 경우**는 별도 답글로 분리하거나 글을 삭제하지 않습니다.
4. OCR 검토 메시지에 게시물 후보 총수와 **답글 후보 수**를 같이 표시합니다.
5. 정확한 날짜가 없는 답글은 날짜 공란 및 `날짜수정필요` 유지, 부모 원글을 관리자 직접 지정하기 전까지 등록 차단. 미확인 작성자 @아이디를 자동 추정하지 않습니다.

## 실제 사례 회귀 테스트
- 제공된 **기본 OCR 전문** (`관련성이 가장 높은 HE v`)과 **보정 OCR 전문** (`관련성이 가장 높은 답글 Vv`) 각각 **원글 1건 + 답글 1건**으로 분리됨.
- 첫 게시물의 작성 시각 **2026-01-16 00:33 KST** 인식. 답글은 날짜 승계하지 않으며 마지막 문장 `제발` 포함.
- 정상 원글, 잘못 인식된/없는 답글 제목, 연속 답글 2건, 본문 속 같은 문구 등 **회귀 10개 사례** 통과.
- Chromium **320/390/768/1280px**에서 실제 제공 OCR 전문을 모의 인식 결과로 공급해 카드 2개 표시, 가로 넘침 없음, 답글 날짜/부모 미확정시 저장 차단 확인.
- `node --check public/capture.js` 및 `node tests/capture-replies.test.cjs` 통과.
- **실제 운영 브라우저가 내려받는 Tesseract.js 한글 모델로 이미지 자체를 다시 읽는 단계**는 이번 패치에서 검증하지 않았습니다. 자동 문자 인식 품질과 답글 본문 일부 누락 문제는 별도로 원본과 비교해야 합니다.

## 적용 및 재시험
1. 현재 GitHub 소스를 백업하고 운영본에서 변경 여부를 비교한 뒤, ZIP의 파일을 원래 경로에 덮어씁니다.
2. GitHub 커밋 → Cloudflare Pages 배포 완료 확인 → 새로고침. `capture.html`은 JS 캐시 버전 `31`을 불러옵니다.
3. 사용자 제공 **같은 원본 캡처**를 Ctrl+V로 다시 넣거나, OCR 결과 입력창에 제공된 기본 OCR 전문을 넣고 `[이 텍스트로 게시물 다시 나누기]`를 누릅니다.
4. 후보 **2건 (답글 1건)** 표시, 첫 글 날짜 `2026-01-16 00:33`, 두 번째 글 본문 및 답글 유형을 확인합니다.
5. 첫 글과 답글 모두 원본 이미지와 비교해서 오타를 수정합니다. 특히 답글의 일부 누락된 문장을 자동으로 복구하는 기능은 아닙니다. 날짜와 부모 관계가 확정되지 않은 글은 보류합니다.

# PIA v0.3.30 — X 모바일 캡처 OCR 필드·본문 분리 정확도 보정

## 적용 기준
- **v0.3.29 무료 정밀 OCR 캡처 등록 기능이 이미 적용된 사이트**에 추가 적용합니다.
- 변경 파일은 `public/capture.js`, `public/capture.html`, `public/capture.css`, `README.md`, `HISTORY.md` 총 5개입니다.
- `admin.js`, `app.js`, `import.js`, 서버 API, D1/DB 스키마, 유료 AI·API 키는 변경하지 않았습니다.
- **운영 GitHub 최신본과 직접 대조한 상태는 아닙니다.** 실제 운영 소스에 후속 변경이 있다면 차이를 먼저 합쳐 적용하세요.

## 제공된 실제 X 스크린샷에서 확인하고 수정한 문제
- X의 `게시하기` 메뉴/조회수/반응 수/툴바/`관련성이 가장 높은 답글`이 하나의 게시물 본문에 섞여 저장 후보가 되던 문제 수정.
- `관련성이 가장 높은 답글` 및 `님에게 보내는 답글`을 이용해 **원글/답글을 별도 후보**로 분리하며, 답글 원글 연결은 사람이 직접 선택하도록 유지.
- **`2026년 01월 16일ㆍ12:33 오전ㆍ조회수 91회` → `2026-01-16T00:33`**: 날짜 뒤에 시각·오전/오후가 오는 X 서식 지원.
- 한글 OCR에서 `@drt CHRM`처럼 아이디가 공백으로 깨졌을 때 `drt`만 잘라 작성자로 확정하던 오류 방지. 알 수 없는 아이디는 공란/검토 상태로 둡니다.
- 동일 이미지의 다른 게시물에서 올바른 @아이디가 발견되면 **직접 확인 후 선택하는 후보 버튼**을 제안합니다. 자동 확정하지 않습니다.
- 전체 캡처는 여러 텍스트 영역으로 구성되어 있으므로 보정본 전체 인식은 `PSM 3`으로 변경. **작은 영역 드래그 재인식은 기존 PSM 6 유지.** 사용자 선택 전까지 기본·보정 결과를 임의 합성하지 않습니다.
- 답글에 `8시` 등 상대 시간만 있으면 정확한 게시일시를 알 수 없으므로 날짜 공란, 등록 차단 유지. 다른 글의 날짜를 임의로 물려주지 않습니다.

## 실제 사례 기준
제공된 캡처에서 다음 결과가 기대됩니다.

| 분리 항목 | 기대 결과 |
|---|---|
| 첫 번째 글 | 1건, 일반 게시물, 2026-01-16 00:33(KST) |
| 두 번째 글 | 1건, 답글 유형(부모 연결은 미확정), 날짜 공란 |
| UI 문구 | `게시하기`, `조회수 91회`, `5 마음에 들어요`, `관련성이 가장 높은 답글`이 본문에서 빠짐 |
| 작성자 | OCR이 `@drt_CHRM`을 정확하게 읽었을 때만 자동 기입. `@drt CHRM`은 공란으로 검토 |

## 검증 범위와 한계
1. 제공된 원본 PNG를 로컬 오픈소스 Tesseract 5 `kor+eng`로 PSM 3/6 및 대비 확대본(PMS 3)으로 실제 OCR 판독했습니다. PSM 3/6 각각 본문 단어 인식에 차이가 있어 정답으로 임의 결합하지 않았습니다.
2. **제공된 OCR 전문 및 로컬 Tesseract 실인식 결과 3종**을 새 파서에 입력하여 모두 **원글 1건·답글 1건 분리, 첫 게시일시 KST 00:33 감지, 메뉴/메타정보 제외**를 확인했습니다.
3. Chromium **320/390/768/1280px**에서 실제 인식된 텍스트를 테스트 입력으로 사용한 화면·필드·등록 안전장치 모의 테스트 통과. JS 문법 및 ZIP 무결성 검사 수행.
4. **실제 배포된 Tesseract.js CDN/WASM의 엔드투엔드 실사 OCR은 재현하지 못했습니다.** 브라우저에서 모델이 인식하는 문자열은 네트워크, OCR 설정, 이미지 스케일에 따라 달라질 수 있습니다.
5. 이 패치는 **OCR 문자를 100% 수정하는 AI가 아닙니다.** `꼬우면` 같은 단어는 기본/보정 결과 중 정확한 쪽을 사람이 고르거나 원본을 보면서 수정해야 합니다. 작성자 아이디, 날짜·답글 연결도 등록 전에 대조해야 합니다.

## 사용 순서
1. 관리자 로그인 → 캡처 자동 등록 → 이미지 붙여넣기(`Ctrl+V`).
2. 정밀 인식에서 **기본 결과와 보정 결과를 비교**. 필요한 경우 명확한 쪽을 적용하거나 특정 영역만 재인식.
3. 후보 **2건**으로 나뉘었는지, 본문에 메뉴·조회수·답글 헤더가 포함되지 않았는지 확인.
4. 작성자가 OCR에서 잘못 읽히면 기존 PIA 계정 선택 또는 직접 교정. 같은 이미지에 @아이디 제안이 나오면 원본 확인 후 선택.
5. 첫 글의 2026-01-16 00:33 시각을 대조하고, 답글 날짜/원글 연결은 확실하지 않으면 보류.
6. 중복 검사를 거쳐 확실한 항목만 등록하고, 작업 중에는 검토 초안 JSON을 내려받아 보관.

# PIA v0.3.29 — 무료 OCR 정밀 인식 + 클립보드 연속 붙여넣기 통합 보정

## 적용 기준 및 범위
- **기준**: 기존 `pia-v0.3.28-free-capture-ocr-admin-patch.zip`의 `/capture.html` 화면과 `/capture.js`, `/capture.css`.
- **교체 대상**: `public/capture.html`, `public/capture.css`, `public/capture.js`, `README.md`, `HISTORY.md` 총 5개.
- v0.3.28이 먼저 적용돼 있어야 **관리자 > 캡처 자동 등록 메뉴**가 나타납니다. 이번 패치에는 v0.3.28의 `admin.html`을 중복 포함하지 않습니다.
- 기존 관리자 `admin.js`, `admin.css`, CSV 검수 `import.js`, 공개 페이지 `app.js`, 서버 Functions, D1 스키마는 변경하지 않았습니다.
- 실 운영 GitHub `main`의 최신 파일과 1:1 확인된 것은 아닙니다. 운영에 추가 수정이 있다면 덮어쓰기 전에 차이를 확인하세요.

## 달라진 점
### 정밀 인식 모드 (기본값)
1. Tesseract.js v5.1.1의 한글·영어 모델로 원본 이미지 OCR을 1회 수행합니다.
2. 브라우저 Canvas에서 **가로 확대(기준 약 1,700px)**, 회색조·명암 대비 강화, 어두운 배경 자동 반전, 최대 900만 화소 제한을 적용해 같은 이미지를 추가 1회 인식합니다.
3. 두 텍스트를 나란히 보여주고 서로 다른 줄(최대 5개 예시)을 표시합니다. **OCR 신뢰도는 참고값**이지 정확도 확정이 아닙니다.
4. 임의로 '더 좋아 보이는' 문장을 덮어쓰지 않습니다. 기본 결과를 먼저 사용하고, 관리자가 [보정 결과 적용]을 클릭해야 바뀝니다(기본 결과가 완전히 비어 있으면 보정본을 검토 초안으로 사용).
5. 작은 @아이디·날짜·문장 영역을 이미지 위에서 드래그 → [선택 영역 정밀 재인식] 가능. 추출된 영역 텍스트는 자동으로 기존 본문에 합치지 않으며, 사용자가 확인 후 복사하거나 명시적으로 추가합니다.
6. 빠른 인식 모드를 선택하면 기존처럼 원본 1회만 읽습니다. 느린 PC에서는 이것을 사용하세요.

### 클립보드·대기열 강화
- Windows: **Win+Shift+S → 영역 캡처 → PIA 페이지에서 Ctrl+V** (맥은 스크린샷 복사 후 Cmd+V). 반복해서 붙여넣으면 들어온 순서대로 이미지가 쌓이고 OCR은 한 장씩 처리합니다.
- [📋 클립보드 이미지 가져오기] 버튼도 제공. 브라우저가 클립보드 읽기 권한을 허용하지 않으면 Ctrl+V를 사용하세요.
- 파일을 고르는 도중이나 반복 붙여넣기 도중 **해시 계산 단계부터 순서대로 처리**하므로 빠른 반복 동작으로 동일 이미지가 중복 등록되는 문제를 줄였습니다. HTTPS 환경에서 SHA-256 중복 검사 사용.
- 1회 선택 20장, 대기열 총 60장, 이미지 한 장 최대 18MB. 브라우저 메모리 부담을 줄이기 위한 제한입니다.
- 이미 등록한 게시물이 있는 이미지에 대해 OCR 재분리로 새 후보를 또 생성하지 않도록 방지합니다.

## 신입 관리자 사용 순서
1. PIA 관리자 로그인 → `📷 캡처 자동 등록` 메뉴.
2. 기본 `정밀 인식` 상태에서 캡처를 붙여넣기(Ctrl+V) 또는 파일 선택.
3. 원본 이미지와 **기본/보정 두 OCR 결과**를 직접 비교하고, 필요하면 [보정 결과 적용].
4. 작은 영역이 틀리면 [작은 영역 직접 선택] → 이미지 위 드래그 → [선택 영역 정밀 재인식] → 나온 문구 확인 및 복사.
5. 추출된 본문·작성자·날짜·원글 관계를 고치고 [이 텍스트로 게시물 다시 나누기].
6. 기존 중복 목록 확인, 작성자·날짜·답글·인용 연결 확인 후 [중복 검사 후 등록].
7. 남은 작업은 **검토 초안 JSON 저장**. JSON에는 이미지 파일 자체가 들어 있지 않으므로 원본 JPG/PNG 파일을 별도로 보관하세요.

## 안전 및 비용
- 유료 AI API, 결제 정보 또는 새로운 서버측 OCR 호출은 사용하지 않습니다. 이미지 OCR 처리는 브라우저 로컬에서 실행됩니다.
- 최초 OCR 프로그램·WASM·kor/eng 모델 다운로드에는 **무료 공개 CDN 연결**이 필요합니다. 완전 오프라인 기능은 아닙니다.
- OCR된 이미지는 서버에 업로드하지 않습니다. 최종 등록을 명시적으로 승인한 경우에만 기존 API에 게시물 텍스트를 전송합니다.

3. **무료 Tesseract.js v5.1.1** 기반 OCR을 관리자 PC/브라우저에서만 실행. 한국어+영어 `['kor','eng']` 인식 모델을 사용. 처음 시작할 때 CDN을 통해 OCR JS, 워커, WASM, 언어 모델을 다운로드하므로 인터넷 연결 필요. 무료 공개 파일로, 유료 API나 추가 결제 필요 없음. `public/capture.js` 내 CDN URL은 버전 고정.
4. 이미지별 OCR 텍스트 수정, 게시물 후보 자동 분리(휴리스틱), 후보 추가, 다시 나누기, 원본 이미지 확대 보기 지원.
5. 후보별 닉네임, @아이디, 계정, 한국시간 원본 날짜, 본문, 답글·인용 유형 및 원글 선택/검색. **답글 관계와 인용 관계를 자동 확정하지 않음.** 미확정 시각은 `날짜수정필요`로 유지.
6. 기존 등록 계정과 연결. 신규 계정은 관리자 확인 후 명시적 생성.

8. **검토 대기 / 보류 / 제외 / 등록 완료**를 구분하며, 보류·제외는 등록 차단. 승인한 글만 기존 `POST /api/posts`를 통해 실제 등록.
9. 초안 JSON 내려받기/다시 불러오기 지원(추출된 글/수정 결과/이미지 파일명 포함; **이미지 원본 파일 자체는 JSON에 포함되지 않음**).

## 사용 순서 (신입 관리자)
1. PIA 관리자 로그인 → `📷 캡처 자동 등록`.
2. 캡처 이미지를 끌어놓거나 파일 선택. 처음 1회는 한글 OCR 모델 다운로드에 시간이 걸릴 수 있음.
3. 각 이미지의 인식 텍스트를 읽고 원본 이미지와 비교. 한 장에 여러 트윗이면 후보가 여러 개로 구분되는지 확인하고, 아니면 후보 추가/다시 나누기로 보정.
4. 후보별 @아이디 / 닉네임 / 본문 / 원본 작성일시 확인. 작성자가 아직 DB에 없으면 **원본 확인 후** 계정 등록.
5. 답글은 원본 게시물 검색 후 원글을 선택. 인용은 기존 원본 연결 또는 직접 작성자/본문 입력.
6. 오른쪽 중복 결과를 보고, 동일 게시물이면 `제외`, 불확실하면 `보류`, 별개인 것이 확인되면 등록.
7. 등록 버튼 클릭 → 최종 확인창 승인. `등록 완료` 상태와 게시물 링크가 표시됨.
8. 작업 중간에 **검토 초안 JSON 저장**으로 결과 보관. 닫고 다시 시작할 때 JSON 불러오기(이미지 미리보기는 다시 선택 필요).

## 무료 운영 및 보안 주의
- OCR 이미지는 **서버로 전송하지 않는다.** 브라우저가 로컬 이미지 파일을 읽어 문자 인식하며, 최종 등록을 승인한 텍스트 정보만 PIA에 POST됨.
- `Tesseract.js` 코드·한글 언어 모델은 외부 무료 CDN에서 내려받는다. 따라서 **완전한 네트워크 오프라인 기능은 아님**. OCR 결과 또는 캡처 이미지 파일을 유료 AI API로 업로드하지 않는다. 제3자 CDN에서 코드를 내려받는 구조인 만큼 공개 공급망 의존성은 존재함.
- 별도 청구는 없지만 Cloudflare Pages / D1의 기존 무료 사용량 한도는 여전히 적용됨.
- OCR은 **글자 인식**이지 X 게시물에 대한 완전한 의미 이해가 아니며 정확도 보장 불가. 인물·답글 관계·본문·인용 구조 및 시간은 반드시 원본 이미지와 직접 대조할 것.
- 날짜가 미검출이면 자동으로 오늘 날짜를 넣지 않으며 **저장할 수 없음**. 날짜만 인식하면 임시 `12:00` 입력과 `날짜수정필요` 상태로 표시하고 사람이 확인해야 함.
- 중복 검사와 최종 등록은 안전장치지만 같은 텍스트가 다른 날 별도로 게시된 사례, OCR 오탈자, 운영 DB 외부 업데이트 등까지 완전 식별을 보장하지 않음.
- 기존 API의 중복 등록 안전장치는 운영 D1에 `migration-v0.3.17.sql`이 적용되어 있어야 함. 이미 해당 마이그레이션을 적용했으면 추가 작업 불필요.

# PIA v0.3.22 — 실제 X 캡처 기준 액션 바 정렬 보정

## v0.3.17 — CSV 중복 등록 이중 방지

### 변경
- CSV 미리보기에서 기존 DB와 CSV 내부의 **동일 계정·동일 본문·동일 작성 시각**을 중복으로 판정하여 **체크 불가** 처리합니다. 본문은 유니코드 NFKC 및 공백 묶음 정규화, 시각은 시간대 포함 절대 시각으로 비교합니다.
- 동일 계정·본문이지만 작성 시간이 다른 게시물은 **중복 후보**로 표시하고 기본 선택을 해제합니다. 실제로 별도 게시물이라면 사용자가 수동 체크하여 등록할 수 있습니다.
- `needs_review`만 있는 행은 계속 기본 선택합니다. 기존 날짜/답글/인용 데이터 및 매칭 방식은 유지합니다.
- 저장 버튼을 누른 직후 최신 DB 데이터를 다시 읽고 중복을 재검사합니다. 저장 중에도 CSV 전용 `import_guard` 플래그를 통해 서버에서 기존 DB와 재비교합니다.
- 서버는 같은 시각의 정규화된 글을 확인하고, 새 CSV 등록 건에 고유 지문을 부여해 `pia_import_keys`에 기록합니다. D1 트랜잭션과 기본키 충돌을 이용해 동시에 실행된 CSV 등록의 중복 삽입을 막습니다.
- **기존에 저장된 게시물은 변경/삭제하지 않으며**, 중복 게시물이 이미 있더라도 마이그레이션을 적용할 수 있습니다. 일반 수동 게시물의 작성·수정 API 동작은 기존대로입니다.

### 반드시 지킬 적용 순서
1. 현재 GitHub 소스가 **v0.3.16까지 반영**되어 있는지 확인하고 운영 D1 백업을 합니다. 이전에 인용 연결 기능을 사용했다면 `migration-v0.3.13.sql`이 적용됐는지도 확인하세요.
2. **`migration-v0.3.17.sql`을 운영 Cloudflare D1에 먼저 1회 적용**합니다. 예: `npx wrangler d1 execute <D1_DATABASE_NAME> --remote --file=migration-v0.3.17.sql` (실제 D1 DB 이름으로 대체).
3. ZIP의 파일을 저장소 루트에 경로 그대로 덮어쓰기 → 커밋 → Cloudflare Pages 배포.
4. CSV 일괄 등록 화면에서 DB와 중복 재검사, 중복 후보 수동 선택, 동일 파일 재업로드 차단을 확인하세요.

### 제한 및 주의
- 일괄 등록에서의 정확한 중복 차단 기준은 **같은 @아이디, 같은 정규화 본문, 같은 작성 시각(동일 절대 시각)**입니다. 서로 다른 시각의 유사 글을 무조건 삭제하지 않습니다.
- 서버가 처리하는 자동 중복 차단은 CSV 가져오기 요청에 한정됩니다. 일반 수동 게시물 저장과 외부에서 임의로 보내는 쓰기 요청 전체를 막는 전역 유일 제약은 아닙니다.
- 기존 DB에 있는 중복 기록을 자동 제거하지 않습니다.
- 실제 Cloudflare 운영 DB/브라우저 배포 검증은 수행하지 않았습니다. JS 문법, 마이그레이션 SQL, ZIP 무결성 및 모의 흐름 테스트만 수행했습니다.

## v0.3.18 — 삭제된 게시물의 검색 잔상 개선

### 수정 범위
- 공개 타임라인: 검색 화면으로 이동하거나 검색어를 다시 검색할 때 `/api/data`의 최신 결과를 요청합니다. 요청 중에는 이전 검색 결과를 잠시 숨겨 삭제된 글이 남아 보이지 않도록 합니다.
- 브라우저 탭 재활성화 및 관리자/공개 화면의 게시물 변경 알림 시 최신 게시물 목록으로 갱신합니다. 새로고침이 실패한 검색 화면에는 이전 게시물을 다시 표시하지 않고 오류를 알립니다.
- 관리자: 게시물 목록 검색, 답글 대상 검색, 인용 원본 검색에서 최신 DB를 다시 읽습니다. 다른 탭에서 게시물이 삭제된 뒤 관리 화면에 돌아오면 검색 목록과 중복 안내를 갱신합니다.
- API: 삭제 대상이 없거나 연결된 답글 때문에 삭제할 수 있는 상태가 아닌 경우 구체적인 오류를 반환합니다. 실제 삭제 행 수를 확인한 후에만 삭제 성공을 반환합니다. **연결된 답글을 자동 삭제하지 않습니다.**
- 스크립트 캐시 버전: `public/index.html`의 `app.js` v39, `public/admin.html`의 `admin.js` v38.

### 설치
1. 현재 최신 PIA 소스가 기존 v0.3.17 기능을 포함하는지 먼저 확인합니다. 이 패치는 업로드된 `pia-main(1).zip`에 이전 통합 패치(v0.3.14~0.3.17)를 순서대로 합친 기준으로 제작했습니다. 실제 운영 GitHub 버전은 확인하지 않았습니다.
2. 이 ZIP을 압축 해제하여 **GitHub 저장소 루트에 같은 경로로 병합**하고 커밋한 뒤 Cloudflare Pages에 배포합니다. 이미 커스터마이즈한 파일이 있다면 덮어쓰기 전에 차이를 비교하세요.
3. 게시물을 삭제한 후 공개 검색, 관리자 목록 검색, 답글/인용 대상 검색에서 해당 ID가 다시 나타나지 않는지 확인합니다. 삭제 실패 시 구체적인 안내 문구를 확인합니다.

### 검증 및 주의
- JavaScript 3개 문법 검사, 검색 결과 최신화 모의 테스트, API 삭제 성공/대상 없음/답글 연결/삭제 0건 모의 테스트 수행.
- DB 마이그레이션 없음. 기존 저장 게시물/계정은 변경하지 않습니다.
